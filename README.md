## 项目介绍

CodeSense = Code + Sense。它从一个很具体的困扰出发：**AI 写出了代码，我却看不懂，也不知道该不该相信它。**

CodeSense 面向代码基础薄弱、正在使用 AI Coding 的人，**以理解 AI 生成代码为首要目标**，逐渐建立独立判断、验证与审查能力。先弄清“它做了什么、为什么这样做”，再逐步练习“它是否满足需求、我的判断有什么证据、还有什么不确定”。

目前它是一套配合 AI 对话使用的 **Markdown 学习流程、案例与记录模板**，属于轻量学习实验，不是独立软件、自动代码审查引擎或已验证有效的通用教学平台。

## 快速开始

### 普通教学体验

把下面内容发给 ChatGPT，体验“解释 → 复述 → 必要纠错”。简单知识不必强制套入完整审查流程。

**这只是普通提示词体验。** 不读取 CodeSense 文件，ChatGPT 也可以完成；因此它不能验证项目规则是否被执行、学习机制是否有效，也不计作正式 Case 成果。

### 正式训练

**首次准备：一份规则全文 + 一段代码及需求。**

第一次开始选题，只需准备：

1. **[learning-loop.md](learning-loop.md) 全文**：下载后上传到同一对话，或直接复制全文。也可让 AI 读取文件链接，但必须确认实际读到了内容，不能只凭仓库地址假定已加载。
2. **一小段代码和需求**：说明它应该做什么，附上来源、文件位置、版本或快照及必要调用条件。没有真实代码时，请 AI 准备明确标注的教学示例，不冒充真实项目 Case。

发送下面的启动词，把方括号内容换成自己的材料；AI 再按规则人工筛选最多 3 个候选，选 1 个开始即可：

<summary>展开并复制：正式训练启动词</summary>

```text
请带我开始一次 CodeSense 正式训练。
规则：优先读取我上传的 learning-loop.md v0.1.4 全文；若从 GitHub 读取，请使用本 PR 分支的 learning-loop.md，合并前不要把 main 的 v0.1.3 当作 v0.1.4。
请先读取全文（或我上传的同名文件），说明实际读到的流程版本。
读取失败或内容不全时，请指出缺哪份材料，等我补充，不要凭 README 或记忆代替规则。

代码与需求：[粘贴代码、预期行为、来源与版本、必要上下文；没有则注明需要教学示例]
我目前的基础和不懂的地方：[简单描述，也可以写“不确定”]

先检查材料是否足够，根据本轮目标、已有回答和可信的掌握证据选择快速澄清、常规理解或专项审查。进入专项审查时：若需要阅读帮助则选引导入口；若能读代码且希望独立测评则选独立评估入口；没有证据时先用一个中性小任务判断，不因为用户自评 U0 就固定使用引导。一次只问一个小任务。
准备题面与记录前补齐练习、教练、结果模板；进入迁移前读取变体规则。
不要提前透露考点、Review 或答案；单对话无法隔离教练依据时，按规则在首次回答后生成并记录时点。
原样保留回答和帮助，区分独立、提示后、讲解后完成；分歧先核对证据。
按流程完成原题闭环后再进入迁移，不跳过解释、复述或验证，不擅自降低通过标准。
暂停或结束时按结果模板整理记录，标明停止位置和下一步；没有保存工具时输出可复制的 Markdown 供我保存。
```

</details>

### 文件读取与记录保存

**AI 读不到 GitHub 时**，打开对应文件，复制全文或下载后上传；链接和文件名本身不能替代内容。出题与首次作答前补齐三个模板，迁移前补齐变体规则，具体文件见下方表格。AI 负责逐步整理，你不必先学会填写全部表格。

新 Case 使用未占用编号，不覆盖已有记录。AI 输出记录后请核对并保存；本项目不会自动写入 GitHub、跨对话同步或设置复测提醒。下次继续时带上题面、结果记录和同版规则。

## 学习机制

**一个 Case = 一个问题母题 + 一个核心判断能力 + 一组迁移变体。**

正式专项审查支持两种入口：需要阅读帮助时先中性讲解与复述，再自行寻找风险；能读代码且希望独立测评时直接首次作答。入口由目标与证据决定，不因自评 U0 固定选择；分别记录帮助程度，不能把接受讲解后的表现当成无帮助的基线。专项训练通常经历：

1. **读懂并复述**：先弄清代码的实际行为，暴露具体理解缺口。
2. **判断并验证**：将结论连接到需求、代码路径和证据；AI 的结论也要核对。原题的原因、修复和验证尚未讲清时，先留在原题。
3. **换题再判断**：用未见变体和延迟复测观察迁移与保留，分别记录独立完成和接受帮助的表现。

“听懂解释”“原题答对”“未见题独立完成”“隔天仍能完成”分别记录，不能相互替代。AI 整理记录，用户负责作答、指出不确定项，并确认原话与帮助记录准确。一次 Case 成功只支持继续实验，不能证明通用能力或整个机制有效。

短练习可按 10～15 分钟安排，完整 Case 可分次；达到当日迁移通过条件后，安排 1～3 天后的未见题复测。正式顺序、通过条件与暂停规则以 [学习流程](learning-loop.md) 为准，README 的概览不改变教学规则。

### v0.1.4：按目标选择学习路径

不是所有提问都要走完整七阶段：旧知识暂忘时用**快速澄清**（简短提醒、必要确认）；看不懂代码时用**常规理解**（讲解、复述、针对缺口补足）；正式独立审查才走原有专项七阶段与迁移复测。无论哪条路径，证据充分就不机械重复，仍有具体误解就深入。

跨语言学习（如 Java → C）先对照已学共同规则与关键差异，只检查尚不确定的部分；各领域分别记录掌握证据，不用 U0 或 L1～L5 给人贴永久等级。未知题独立诊断前不泄露缺陷线索；接受提示后不追认独立成绩。

正式训练的执行与判定仍以 [learning-loop.md](learning-loop.md) 为准；[v0.1.4 测试方案](docs/test-plan-v0.1.4.md)列出 A–H 场景，测试方案本身不是通过证据。

## 使用边界

模板只是记录结构，不是自动化工具；教练文件只是展示隔离，不是访问控制。已看过答案须如实记录，另用新题评估。手动推演不能写成实际运行，有限测试不能证明代码全面可靠。

### 与个人 Coding SOP 的关系

SOP 管回退、密钥、修改和运行风险；CodeSense 训练“证据自己看得懂”。做练习不代表授权修改源项目。涉及真实修改或发布时，另按当前个人 SOP 执行。训练完成不代表代码可以发布；“未发现问题”不能自动等同于“安全”。
