# CodeSense

> 从看懂 AI 代码，到逐渐拥有独立判断能力。

**Experimental · MVP v0.1.3 · 学习机制待验证**

CodeSense = Code + Sense。它从一个很具体的困扰出发：**AI 写出了代码，我却看不懂，也不知道该不该相信它。**

CodeSense 面向使用 AI Coding、代码基础仍薄弱的学习者，是一个以理解 AI 生成代码为首要目标，逐渐建立独立判断、验证与审查能力的轻量学习实验。目前通过 Markdown 案例、学习流程和记录配合 AI 对话使用；还不是独立软件、自动代码审查引擎或已验证有效的通用教学平台。

先用一小段代码弄清“它做了什么、为什么这样做”，再逐步练习“它是否满足需求、我的判断有什么证据、还有什么不确定”。

## 先在 ChatGPT 里试一小段

不必先完成整套专项审查。可以从自己的一个函数开始，附上需求和不理解的地方。没有真实代码时，也可以用下面这个**教学示例**体验代码讲解；这不是正式 Case 评估或 v0.1.4 自适应机制已实现的证明。

把以下内容复制到 ChatGPT：

````text
我想先看懂这段 AI 生成的 Java 代码。
需求：根据单价与数量计算总价。本例只讨论普通非负整数，不讨论溢出。

```java
int totalPrice(int unitPrice, int quantity) {
    return unitPrice * quantity;
}
```

请先用普通话解释输入、计算和返回值，并用单价 8、数量 3 举例。
然后让我用自己的话复述；若有具体误解，再围绕误解补充说明。
这次只体验代码理解，不作正式 Case 通过判定。
````

真实代码请补充来源、文件位置、版本和原始需求；不要把教学示例写成真实项目验证。若之后想专项训练“能否独立判断”，再进入下面的 Case 流程。

## 开始一次专项审查训练

当前 v0.1.3 的完整流程见 [学习流程](learning-loop.md)：从中性阅读与复述或首次独立判断开始，经证据核对、原题原因与修复闭环，再进入未见变体与延迟复测。

一个 Case = 一个问题母题 + 一个核心判断能力 + 一组迁移变体。“听懂解释”“原题答对”“未见题独立完成”“隔天仍能完成”分别记录，不能相互替代。

1. 向 ChatGPT 提供 [学习流程](learning-loop.md) 和代码、需求，请 AI 人工筛选最多 3 个候选，选 1 个即可。需要其他模板时再补充对应文件，不假设 AI 已读过整个仓库。
2. 使用 [练习模板](cases/_template.md)、[教练模板](cases/_template-coach.md) 和 [结果模板](results/_template-result.md)。库存 `case-001` 已存在；新 Case 使用未占用编号，不覆盖旧记录。教练依据在作答前不要展示。
3. 先保留原始判断，再诊断和教学；按 [变体规则](docs/variation-generation.md) 逐题验证。U0 每次约 10～15 分钟，完整 Case 可分次；满足条件后安排 1～3 天的延迟复测。

AI 整理记录，用户主要负责作答、指出不确定项和确认记录准确，不必同时填写多份表。

可直接对 AI 说：

> 请按我提供的 CodeSense learning-loop.md 带我完成一个 Case。先检查代码和需求是否足够，默认用 U0 引导模式，只给我中性的练习页，一次问一题，等我回答后再反馈。不要先展示考点、Review 或答案；原样保留我的回答，区分独立完成和提示后完成。有争议先核实证据，不要默认我错了。验证后先完成原因、修复、验证和复述，不要直接跳到变题。缺少真实代码时可明确标注教学示例。

## 与个人 Coding SOP 的关系

SOP 管回退、密钥、修改和运行风险；CodeSense 训练“证据自己看得懂”。做练习不代表授权修改源项目。涉及真实修改或发布时，另按当前个人 SOP 执行。训练完成不代表代码可以发布；“未发现问题”不能自动等同于“安全”。

## v0.1.3 修订（历史记录）

- 加入 U0 引导与独立评估两种入口，分别记录帮助，避免夸大学习效果。
- 验证后补原因、最小修复、修复验证及用户复述，满足条件才进入迁移。
- 每周短练习控制 10～15 分钟，Case 可分次完成；一次问一个小任务。
- 保存教学试跑原话与流程缺口；已展示的钱包题不能作为未见题。
- 更新模板与变体规则，保留旧版的能力边界和真实项目交接规则。

## v0.1.2 修订

- 在学习流程第 11 节加入知识不足、证据不足与未察觉盲区的处理方式。
- 结果模板增加相关边界检查及“已能判断 / 仍不确定 / 下一步”三行收尾。
- 明确训练完成与真实项目修改、发布的交接边界；影响答案依据的新疑点须暂停判定。
- 不新增文件或自动化系统，保留现有七份 Markdown 文档。

## v0.1.1 修订

- 把题面与教练记录分开，修复模板提前透露考点的问题。
- 统一首次作答与 Review 的顺序，AI 结论须经需求和证据核对。
- 用“结论、依据、边界、验证”四项评估，并单独记录提示程度。
- 加入无缺陷变体、需求变化、延迟复测和有限循环。
- 消除模板重复记录、章节编号重复和“变体就是新 Case”的混用。
