# CodeSense

> 用真实代码、解释、对照和迁移验证，训练 AI Coding 使用者自己的代码判断能力。

**Experimental · MVP v0.1.3 · 学习机制待验证**

CodeSense = Code + Sense。我们关心的是：原来必须依靠 AI 才能判断的问题，经过学习以后，用户能否自己给出结论和证据？当前版本是 Markdown 学习实验框架，不是自动审查产品。

## 核心假设

小型代码 → 阅读与复述（U0）或首次独立判断 → 提出风险 → 证据核对 → 原因与最小修复 → 修复验证与复述 → 原题复判 → 未见变体 → 延迟复测。

一个 Case = 一个真实问题母题 + 一个核心判断能力 + 一组迁移变体。

“听懂解释”“原题答对”“未见题独立完成”“隔天仍能完成”分别记录，不能相互替代。一个 Case 的成功只是继续实验的依据，不能证明整个系统有效。

## 从这里开始

1. 提供真实项目中的一小段代码、文件位置、版本和原始需求。没有真实代码时可以用明确标注的教学示例试跑；不能把它当作真实项目案例或真实来源验证。
2. 请 AI 按 [学习流程](learning-loop.md) 人工筛选最多 3 个候选，选 1 个即可。
3. 复制 [练习模板](cases/_template.md) 为 `cases/case-001.md`；复制 [教练模板](cases/_template-coach.md) 为 `cases/case-001-coach.md`。后者在作答前不要展示给学习者。
4. 复制 [结果模板](results/_template-result.md) 为 `results/case-001-result.md`。先原样记录首次判断，再诊断、教学和反馈。
5. 按 [变体规则](docs/variation-generation.md) 逐题完成迁移验证；U0 每次约 10～15 分钟，完整 Case 可以分次，没做完可以暂停。1～3 天后安排一次未见题复测。

AI 整理记录，用户主要负责作答、指出不确定项和确认记录没有歪曲原意。默认一个对话逐题推进，不要求用户同时填写多份表。

可直接对 AI 说：

> 请按 CodeSense learning-loop.md 带我完成一个 Case。先检查代码和需求是否足够，默认用 U0 引导模式，只给我中性的练习页，一次问一题，等我回答后再反馈。不要先展示考点、Review 或答案；原样保留我的回答，区分独立完成和提示后完成。有争议先核实证据，不要默认我错了。验证后先完成原因、修复、验证和复述，不要直接跳到变题。缺少真实代码时可明确标注教学示例。

## 文件用途

| 文件 | 用途 |
|---|---|
| [learning-loop.md](learning-loop.md) | 唯一的执行顺序、评估标准和暂停规则 |
| [cases/_template.md](cases/_template.md) | 学习者可见的题面；母题和变体都可使用 |
| [cases/_template-coach.md](cases/_template-coach.md) | 考点、参考判断、证据与出题检查 |
| [results/_template-result.md](results/_template-result.md) | 原始回答、提示、表现和后续行动 |
| [docs/mvp-scope.md](docs/mvp-scope.md) | v0.1 边界和实验结论的限制 |
| [docs/variation-generation.md](docs/variation-generation.md) | 变体生成与防泄题规则 |

教练文件只是展示隔离，不是访问控制。若学习者已读过答案，诚实标记暴露情况，用新的题目评估；不要把已见题算成独立迁移。

## 与个人 Coding SOP 的关系

SOP 管回退、密钥、修改和运行风险；CodeSense 训练“证据自己看得懂”。做练习不代表授权修改源项目。涉及真实修改或发布时，另按当前个人 SOP 执行。训练完成不代表代码可以发布；“未发现问题”不能自动等同于“安全”。
