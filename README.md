# CodeSense

> 从看懂 AI 代码，到逐渐拥有独立判断能力。

**Experimental · MVP v0.1.3 · 学习效果待验证**

AI 写出了代码，自己却看不懂，也不知道该不该相信它——CodeSense 从这个困扰出发，帮助代码基础薄弱、正在使用 AI Coding 的人，逐步建立理解、验证和独立判断能力。

目前它是一套配合 AI 对话使用的 **Markdown 学习流程、案例与记录模板**，属于轻量学习实验，不是自动代码审查工具或独立软件。

## 快速开始

- **只想体验讲解方式**：用下面的小示例，不需要项目文件。
- **想按 CodeSense 规则训练**：使用“最简正式启动”，先让 AI 读到规则全文。

### 普通教学体验：复制即可

把下面内容发给 ChatGPT，体验“解释 → 复述 → 必要纠错”。简单知识不必强制套入完整审查流程。

```text
我想看懂这段 Java 教学示例：
int totalPrice(int unitPrice, int quantity) {
    return unitPrice * quantity;
}
需求：按单价和数量计算总价，只讨论普通非负整数，不讨论溢出。
请用单价 8、数量 3 解释输入、计算和返回值，再让我用自己的话复述。
若有具体误解，再针对性说明。这次只体验代码理解，不作正式 Case 判定。
```

**这只是普通提示词体验。** 不读取 CodeSense 文件，ChatGPT 也可以完成；因此它不能验证项目规则是否被执行、学习机制是否有效，也不计作正式 Case 成果。

### 最简正式启动：先提供一份规则和学习材料

第一次开始选题，只需准备：

1. **[learning-loop.md](learning-loop.md) 全文**：下载后上传到同一对话，或直接复制全文。也可让 AI 读取文件链接，但必须确认实际读到了内容，不能只凭仓库地址假定已加载。
2. **一小段代码和需求**：说明它应该做什么，附上来源、文件位置、版本或快照及必要调用条件。没有真实代码时，请 AI 准备明确标注的教学示例，不冒充真实项目 Case。

随后发送下面的启动词，把方括号内容换成自己的材料：

```text
请带我开始一次 CodeSense 正式训练。
规则：https://github.com/qianzhi1212/Code-Sense/blob/main/learning-loop.md
请先读取全文（或我上传的同名文件），说明实际读到的流程版本。
读取失败或内容不全时，请指出缺哪份材料，等我补充，不要凭 README 或记忆代替规则。

代码与需求：[粘贴代码、预期行为、来源与版本、必要上下文；没有则注明需要教学示例]
我目前的基础和不懂的地方：[简单描述，也可以写“不确定”]

先检查材料是否足够，默认用 U0 引导模式，一次只问一个小任务。
准备题面与记录前补齐练习、教练、结果模板；进入迁移前读取变体规则。
不要提前透露考点、Review 或答案；单对话无法隔离教练依据时，按规则在首次回答后生成并记录时点。
原样保留回答和帮助，区分独立、提示后、讲解后完成；分歧先核对证据。
按流程完成原题闭环后再进入迁移，不跳过解释、复述或验证，不擅自降低通过标准。
暂停或结束时按结果模板整理记录，标明停止位置和下一步；没有保存工具时输出可复制的 Markdown 供我保存。
```

**AI 读不到 GitHub 时**，打开对应文件，复制全文或下载后上传；链接和文件名本身不能替代内容。出题与首次作答前补齐三个模板，迁移前补齐变体规则，具体文件见下方表格。AI 负责逐步整理，你不必先学会填写全部表格。

新 Case 使用未占用编号，不覆盖已有记录。AI 输出记录后请核对并保存；本项目不会自动写入 GitHub、跨对话同步或设置复测提醒。下次继续时带上题面、结果记录和同版规则。

## CodeSense 怎样帮助你学习

一个 Case 围绕一个主要判断能力展开；现行规则支持 U0 引导和独立评估两种入口。以 U0 为例：

1. **读懂并复述**：先弄清代码的实际行为，暴露具体理解缺口。
2. **判断并验证**：将结论连接到需求、代码路径和证据；AI 的结论也要核对。原题的原因、修复和验证尚未讲清时，先留在原题。
3. **换题再判断**：用未见变体和延迟复测观察迁移与保留，分别记录独立完成和接受帮助的表现。

U0 每次约 10～15 分钟，完整 Case 可分次；正式顺序、通过条件与暂停规则以 [学习流程](learning-loop.md) 为准。**听懂解释不等于能够独立判断，一次 Case 成功不等于具备通用能力。**

## 当前版本与验证状态

- **main · v0.1.3**：已有流程、三类模板及部分教学试跑记录。本版重点是 U0 入口和原题闭环；规则存在不等于教学效果已验证。
- **v0.1.4-test · 测试方向**：按交接说明已有测试包；自适应教学、按知识难度调整、跨语言提示仍待验证，尚未作为正式规则进入 main。
- **v0.2～v0.4 · 未来候选**：学习连续性、渐进训练与选题、真实代码工作流。详见 [路线图](docs/roadmap.md)，版本号不是发布承诺。

## 已有案例与实际试跑结果

[库存教学题](cases/case-001.md) 和 [2026-10-10 试跑记录](results/case-001-result.md) 保留了：用户自行提出负数疑点，在 AI 给定输入后正确手算，以及“尚未讲透就进入变题”的流程问题。

**证据范围**：这是教学示例，没有真实项目来源，也未实际运行 Java；仓库记录仍停在原题闭环，尚无独立迁移和延迟复测通过记录。题目已暴露答案，只供回看，不能再作为未见题评估。不能把这次试跑写成整个机制已有效。

模板只是记录结构，不是自动化工具；教练文件只是展示隔离，不是访问控制。已看过答案须如实记录，另用新题评估。手动推演不能写成实际运行，有限测试不能证明代码全面可靠。

个人 Coding SOP 负责回退、密钥、修改与运行风险；CodeSense 帮助你理解判断依据。练习不代表授权修改源项目，训练通过不代表代码可以发布；真实修改或发布仍按个人 SOP 单独处理。
