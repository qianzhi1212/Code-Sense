# CodeSense｜轻量案例管理规范（v0.1.4）

> 本文只约定**人工管理与审核规则**，不建设数据库、自动题库、定时 Case Factory 或 LeetCode 式刷题系统。先看懂代码，再训练有证据的独立判断。

## 三个独立维度

- **审查深度**：L1 基础阅读、L2 算法与边界、L3 业务逻辑、L4 工程实践、L5 系统审查。标签描述案例，不是学习者的永久等级；难度以真实试测修订。
- **领域**：例如条件、循环、算法、业务、工程、并发、安全；一题可有少量标签。
- **用途**：诊断 / 学习 / 未见迁移。已公开参考答案的题不得作为真正未见诊断。

## 最小登记

每个候选记录：`id`、`title`、`language`、`depth`、`domain_tags`、`purpose`、`status`、`revision`、`source_and_license`、`verification`、`learner_path`、`coach_location`。状态只用 `candidate → reviewed → trial → published` 或 `archived`，保留审核与变更理由。候选编号如 `C-20261013-01`；正式题继续沿用未占用的 `case-XXX`，不要覆盖历史。

## 人工入库门槛

1. 核对来源、许可、明确需求、代码及必要前提；允许代码正确，不强制制造 Bug。
2. 审查教练参考：需求条款、代码路径、边界、验证证据；区分静态推演与实际运行。
3. 按核心判断机制、代码结构和能力标签去重，不能只比较标题。
4. 用真实学习者试测题面清晰度、难度和提示泄露风险；未实测不能声称区分度已验证。
5. 审核通过才发布；失败与修订保留历史，版本改变不能悄悄覆盖原有学习记录。

## 隔离和存放

现有 `cases/` 保留正式题，`results/` 保留原始学习记录。现阶段可人工维护候选清单，不要求新增 `bank/` 目录或 CSV。**公开仓库中的 coach 文件不是秘密**；真正用于未知诊断的参考答案与未见题应放私有位置，并避免在公开 PR 中泄露。公开案例适合学习与复盘，不适合未见能力测量。

Astra 生成的 L2 区间案例目前只可登记为候选，不能凭自动测试次数断言教学区分度，更不应自动合并。
