# CodeSense MVP Scope v0.1.3

## 只验证一个假设

真实代码判断 → 证据核对 → 缺口学习 → 重新判断 → 未见题迁移，这个闭环是否值得继续实验？

第一轮只做一个真实 Case，训练一个主要判断能力，记录首次表现、教学帮助、两道当日迁移题和一次延迟复测。U0 单次预算为 10～15 分钟，独立评估会话可约 30 分钟，不要求全部阶段在同一天结束。具体通过与暂停标准以 [学习流程](../learning-loop.md) 为准。

## 包含与不包含

| v0.1 包含 | 暂不包含 |
|---|---|
| 人工浏览小范围代码、筛选候选 | 全仓自动扫描和难度排序系统 |
| Markdown 题面、教练记录、结果 | Web UI、IDE 插件、GitHub App |
| AI 辅助 Review、解释、出变体 | Agent 编排、自动出题引擎 |
| 需求、代码与可检查证据核对 | 自建审查引擎、大型知识库、RAG |
| 用户作答与原始过程记录 | 数据库、积分等级、复杂用户画像 |

不要求为本项目编写软件。确需验证案例行为时，可使用小型本地验证，但要区分静态推演与实际运行；真实项目的修改和运行仍按个人 SOP 处理。

## 第一轮交付什么

- 一个来源和需求明确的真实母题。
- 分开的学习者题面与教练依据。
- 保留原话、失败尝试和帮助程度的结果记录。
- 一项基于实验的流程调整建议；没有结果时不虚构结论。

AgentWeave 的 `frontend/src/utils/validation.ts` 只是候选来源。在获得实际文件、版本和需求前，不宣称已检查过，也不预设其中一定存在缺陷。

## 怎样解释实验结果

- 流程能跑完：只说明流程可执行。
- 原题复判更好：说明对已学材料的理解表现改善，可能包含记忆影响。
- 未见题独立通过：提供有限的迁移迹象。
- 延迟未见题通过：增加能力保留的证据。
- 首次已通过：无法用此 Case 证明学习增益。

单人、单 Case、没有对照的前后比较不能证明因果或普遍有效。题目难度不一致、提示泄露和需求改变都可能干扰解释，须如实记录。当前不加入统计实验平台；先找出明显的流程问题，再积累更多 Case。

## 什么时候考虑自动化

多个真实 Case 后，如果重复步骤稳定，且记录或出题成为主要负担，再只自动化最费力的一步。规则尚不稳定时，优先调整模板。GitHub 可从 Experimental v0.1 开始记录真实版本与实验，不能把模板当成完成案例。


## 能力边界补充

按学习流程第 11 节，在本轮评估后进行相关边界检查，区分已验证、待验证与本次未覆盖，并填写三行收尾。此机制用于减少盲信，不能保证发现全部隐蔽漏洞。

训练目标达成与项目风险解决分开记录。真实修改或发布另按个人 Coding SOP 执行，不能以 Case 通过替代发布判断；影响参考答案或通过依据的新疑点须先核实。当前不新增自动扫描、风险评分或多模型审查系统。

## 教学试跑与真实实验

教学示例用于检查互动流程，须写明无真实项目来源。当前库存试跑提供了一个流程问题的证据，不能证明整个系统有效。真实 Case 仍需实际文件、版本、需求与来源。默认 Java，不建设额外软件或自动化系统。
