# CodeSense 版本路线图

> 从看懂 AI 代码，到逐渐拥有独立判断能力。

CodeSense 的起点是“AI 写出的代码，自己看不懂”。先帮助学习者理解一小段代码，再用复述、验证与未见题逐渐积累自己的判断依据。独立审查是逐步训练的能力，不是使用项目的前置门槛。

这是轻量学习实验的方向记录，不是软件功能发布表。**版本号不是承诺**：测试不支持某项机制时，可以延后、拆分或取消，不为填满版本号而添加功能。

## 当前基线与证据范围

以下是 **2026-10-13（北京时间）的历史基线快照**，不表示未来的实时分支状态：

- [库存记录](../results/case-001-result.md) 支持的观察是：用户自行提出负数疑点，能在 AI 指定输入后正确手算，并指出过早进入变题的流程问题。该记录未完成原题闭环、独立迁移或延迟复测，不能据此宣称通用学习效果。

## v0.1.4：先验证教学是否更合适

以下是 v0.1.4 机制的验收要点；是否已合并或发布应以 GitHub 实际记录为准。

1. **动态学习路径。** 概念一提醒便懂时快速澄清；常规代码理解用“讲解 → 复述 → 必要确认”；专项审查使用完整七阶段路径。按目标和实际表现选择，不要求三套流程逐一打卡。
2. **按需决定讲解深度。** 有充分理解证据时停止重复追问；发现具体缺口时深入解释。简洁和详细都服务于理解，不靠固定篇幅判断教学质量。
3. **分领域渐进难度。** 分开记录题目固有难度、该领域的掌握证据与主观体验；条件判断掌握得好，不推定循环、函数也已掌握。一次主要调整一个维度。
4. **跨语言迁移提示。** 已有 Java 掌握证据时，学 C 先讲共同点、关键差异和易混点，只检查新增差异；独立审查题不提前泄漏风险线索。
5. **证据评估与纠错。** 选择正确且解释合理，原则上足以通过当前理解检查；不能仅猜测用户“蒙对”就机械追问。判为理解不足须指出具体证据，先排除题面缺失，允许复核和更正。理解检查通过不自动等于正式 Case 独立通过。
6. **帮助程度与验证真实性。** 区分独立、提示后和讲解后完成；手动推演不能写成实际运行，有限回归测试不能写成代码全面可靠。
7. **学习节奏与暂停恢复。** 疲劳或阶段未完成时保存证据、停止位置和下一步，不强迫一次结束整个 Case。

### 进入正式版前要看到什么

用具体试跑核对下面的表现，不能只凭规则文件存在就写“已验证”。

| 验收重点 | 需要保留的可检查记录 |
|---|---|
| 必要时能深入 | 知识缺口、针对性解释、用户后续复述及仍未解决的问题 |
| 已掌握不重复 | 已有理解证据、停止追问的依据；若继续提问，说明新增检查目的 |
| 跨语言不重学公共概念 | 已有语言的掌握依据、两种语言的异同、只针对差异的检查结果 |
| 难度按局部能力调整 | 具体领域、调整前后题目及主要改变维度，不用单一总等级代替 |
| AI 判错能纠正 | 原判断、用户质疑、核对依据、修订后的评估，保留用户原话 |
| 测试证据真实 | 输入、预期、手算或实际运行标记、实际结果（若运行）、提示程度与覆盖限制 |
| 现有机制无重要回归 | 专项审查仍不提前泄题；原题未闭环时不跳题；暂停后能据记录继续 |

每轮复盘记录“保留什么、调整什么、为什么”，优先只调整一个主要机制问题。试跑顺畅只支持该场景下流程可行；普遍有效、长期保留和跨领域迁移仍需额外证据。

## 取舍与远期触发条件

| 决定 | 内容 | 依据或重新考虑的条件 |
|---|---|---|
| 接受 | 先测学习机制，再修正文档与模板 | 小范围真实记录足以暴露流程问题，先确保用户看得懂、能继续 |
| 不采用 | 把所有学习强制变成专项审查；按版本号堆功能；把规则写入当成效果验证 | 偏离“先看懂代码”的初心，且不能提供可靠学习证据 |
| 暂缓 | 自动扫描、自建审查引擎、复杂画像与大型平台 | 当前缺少必要性证据，仍遵守 [MVP 范围](mvp-scope.md) |
| 条件触发 | 跨模型／跨用户对照 | 有足够来源明确、需求固定的案例与可复用记录，能够区分提示、题目差异等干扰后再设计 |
| 条件触发 | 学习可视化 | 积累足够分领域证据，且文字记录难以回答“学会什么、仍缺什么”时再做；不制造虚假精确分数 |
| 条件触发 | 轻量脚本或 UI | 多个真实 Case 中重复手工步骤稳定成为瓶颈时，只自动化最费力的一步 |

## 当前唯一前瞻规划：v0.1.4 收尾与后续方向（2026-10-13）

v0.1.4 的范围只稳定化按需路径、跨语言知识复用、局部能力难度调整、独立诊断防泄题与 AI 评估纠错；原有七阶段、四项审查、变体和延迟复测继续有效。**此处记录候选，不倒改上文 v0.1.3 当时的版本事实。**

| 阶段 | 候选方向 | 不在 v0.1.4 实现的内容 |
|---|---|---|
| v0.1.5 | 高区分度首题、按领域校准分流 | 一题判定综合能力或自动评级 |
| v0.2 | 算法／业务／工程案例深度、轻量索引与学习连续性 | 大型题库网站、未经审核自动入库 |
| v0.3 | 真实 PR、Diff、多文件、并发、事务、安全与回归审查 | 用单函数题宣称企业级能力 |
| 研究方向 | Astra / Work 生成候选题并由人审 | 定时自动出题、自动合并、版权不明的题目搬运 |

L1～L5 表示**案例审查深度**而非用户永久等级。v0.1.4 仅增加[人工案例管理规范](case-management.md)，不实施题库系统；原先 v0.2～v0.4 的规划仅作为上方历史版本记录，不再构成并行的当前路线。当前版本安排以本节为准；具体推进仍待验证。
